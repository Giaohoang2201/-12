과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교 (C 구현)
1. 구성 및 실행 방법

gcc -O2 -o quick_sort_pivot quick_sort_pivot.c
./quick_sort_pivot        # 과제 출력 (n = 1,000 ~ 20,000, 보너스 포함)
./quick_sort_pivot avg    # 보조 실험: 200세트 평균
데이터: 0 ~ 1,000,000 범위의 무작위 정수(중복 허용), 시드 고정(srand(12345))
n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
각 n에서 세 방법은 동일한 원본 데이터의 복사본을 사용한다. 정렬 후 오름차순 여부를 확인하고, 표준 qsort 결과와 비교하여 원소가 보존되었는지도 검증한다.
분할(Partition)은 Lomuto 방식 하나만 사용하고, 피벗을 고르는 함수만 교체한다.
비교 횟수 = 분할 중 (데이터 값 vs 피벗 값) 비교 + Median-of-Three의 중앙값 결정 비교(2~3회). 인덱스·종료 조건 검사, 난수 생성, 데이터 이동은 포함하지 않는다.
Random 피벗은 xorshift64 난수를 사용하며, 정렬을 시작할 때마다 같은 시드로 초기화한다.

3. 분석
3.1 데이터 크기에 따른 변화

세 방법 모두 n이 2배가 될 때 비교 횟수가 약 2.2배로 늘어난다(평균 기준 Median-of-Three 2.17~2.22배, First 2.19~2.28배). 이는 O(n log n) 증가의 전형적인 모습이다. n이 2배가 되면 n·log n은 2배보다 조금 더 증가하기 때문이다. 최악의 경우(O(n²))에 해당하는 급격한 증가는 어떤 방법에서도 나타나지 않았는데, 입력이 무작위이기 때문이다.

3.2 피벗 선택 방법별 차이
1세트 실행(2.1)은 순위가 일정하지 않다. n=2,000에서는 First가, n=4,000에서는 Random이, n=8,000과 20,000에서는 Median-of-Three가 가장 적었다. 하나의 데이터에서는 분할이 우연히 얼마나 균형 잡혔는지에 따른 편차(이번 실험에서 같은 n의 방법 간 최대 약 17%)가 방법 간의 평균적 차이보다 크기 때문에, 이 표만으로 방법의 우열을 결론 내리면 안 된다.
200세트 평균(2.2)에서는 경향이 분명해진다. Median-of-Three가 모든 n에서 가장 적었고, n이 커질수록 First와의 차이가 1.2% → 5.8%로 벌어졌다. 반면 First와 Random은 거의 같았다(차이 ±1.5% 이내).
n·log₂n 대비 비율도 같은 결과를 보여 준다. Median-of-Three는 1.08 → 1.12로 완만하게 증가한 반면, First와 Random은 1.10 → 1.19로 더 빠르게 증가했다.
3.3 피벗 선택이 분할과 비교 횟수에 영향을 주는 이유

분할은 구간의 모든 원소를 피벗과 한 번씩 비교하므로 분할 1회의 비용은 구간 길이에 비례한다. 따라서 전체 비교 횟수는 분할로 생기는 두 부분 구간의 크기가 얼마나 균형 잡혔는가로 결정된다. 피벗이 중앙값에 가까울수록 구간이 절반씩 줄어 재귀 깊이가 log n에 가까워지고, 치우칠수록 깊이가 깊어져 같은 원소가 더 많이 비교된다.

First: 무작위 데이터에서 구간의 첫 원소는 구간 안의 값과 무관하므로 피벗의 순위가 균등하게 분포한다. 기대 비교 횟수는 약 2n·ln n(≈1.39·n·log₂n)이다. 단, 이 방법은 입력 순서에 의존한다. 이미 정렬된(또는 역정렬된) 입력에서는 매번 최솟값/최댓값이 피벗이 되어 한쪽 구간이 비고 n(n−1)/2번을 비교하게 된다. (이번 실험은 무작위 데이터만 사용했으므로 직접 측정하지는 않았다.)
Random: 피벗의 순위가 입력 순서와 상관없이 균등 분포이므로 기대 비교 횟수는 First와 같다. 평균 실험에서 두 방법이 거의 같은 값을 보인 것이 이 이론과 일치한다. Random의 장점은 평균이 더 낮다는 것이 아니라, 특정 입력에서 최악의 경우가 반복되는 것을 막아 준다는 것이다.
Median-of-Three: 세 값의 중앙값은 최소·최대가 될 가능성이 낮고 중간 순위로 몰리는 경향이 있어 분할이 더 균형 잡힌다. 이론상 기대 비교 횟수는 약 (12/7)·n·ln n(≈1.19·n·log₂n)으로 First보다 약 14% 적다. 실험에서 관찰된 감소폭(최대 약 6%)이 이론값보다 작은 것은, 중앙값을 구하는 데 분할마다 2~3회의 추가 비교가 들고, 구간이 작아질수록 이 추가 비용의 비중이 커지기 때문이다. 이 때문에 n이 작을 때(1,000)는 이득이 거의 없다(−1.2%).
3.4 어떤 방법이 효과적이었는가

평균 실험에서 Median-of-Three가 모든 데이터 크기에서 비교 횟수가 가장 적었고, n이 클수록 이득이 커졌다. 추가 비교 비용을 감안하고도 더 균형 잡힌 분할로 얻는 이득이 더 컸기 때문이다. Random은 평균 성능이 First와 같지만 정렬된 입력 같은 특정 패턴에 약하지 않다는 안전성이 있다. 다만 기본 실행(1세트)만 보면 순위가 일정하지 않으므로, 피벗 방법을 비교할 때는 여러 데이터에 대한 평균이 필요하다는 점도 실험에서 확인할 수 있었다.

4. [보너스] 재귀적 vs 반복적 퀵 정렬
반복적 구현은 (lo, hi) 구간을 스택(배열)에 넣고 꺼내며 처리한다. 분할 함수와 피벗 선택(Median-of-Three)은 재귀 버전과 완전히 동일하며, 오른쪽 구간을 먼저 push하여 재귀 버전과 같은 순서(왼쪽 먼저)로 처리한다. 프로그램은 두 구현의 비교 횟수가 같은지 확인한다.
측정: n = 10,000, 피벗 Median-of-Three, 데이터 생성·배열 복사·출력 시간 제외, 2,000회 평균(워밍업 후 재귀/반복을 번갈아 4라운드 측정, gcc -O2, clock_gettime으로 ms 단위 측정)

시간의 대부분은 분할 함수 안의 비교·교환 반복문(약 10⁵번 이상)이 차지한다. 재귀와 반복이 다른 부분(함수 호출 약 2n번 vs 스택 push/pop 약 2n번)은 그에 비해 매우 작다.
재귀는 호출마다 스택 프레임을 만들고 복귀 주소를 저장하는 비용이, 반복은 배열에 구간을 저장하고 읽는 비용이 든다. 최적화(-O2)된 C에서는 두 비용이 모두 몇 ns 수준이라 서로 비슷하다.
시간보다 안정성의 차이가 더 중요하다. 재귀 버전은 분할이 극단적으로 치우치는 경우(예: First 피벗으로 정렬된 대용량 데이터) 재귀 깊이가 O(n)이 되어 호출 스택이 넘칠 수 있다. 반복 버전은 호출 스택 대신 직접 할당한 배열을 쓰므로 이 제한을 직접 통제할 수 있다.
